# Stage 3: сборка и приёмка занятия

Этот skill ведёт одно занятие по M1–M5 и подключает конкретные операции автора. [Методички Stage 3](../../../docs/make%20les%20stage/3%20stage/README.md) задают план, учебные правила, ограничения и приёмку каждого шага. Теорию исполняет [theory-author](../stage-3-theory-author/SKILL.md), практику — [practice-author](../stage-3-practice-author/SKILL.md), схемы и интерактивы — [visual-author](../stage-3-visual-author/SKILL.md). Это инструкции того же чата, без запуска отдельных исполнителей.


## Обязательный результат

В M1 сразу создай обязательный каркас обычного занятия: 00 с LinkedNotes variant="connected" и точными пунктами «Точка старта», «Новый вопрос», «Результат»; последний учебный раздел «Что мы будем делать в практике»; учебный визуал и содержательный интерактив вне 00. После первой целой версии выполни `node tooling/courses/lesson_structure.cjs <свой-TSX>`. Импорт/кусок кода не заменяют вставку. M3 проверяет собственный путь решения по теории при закрытых подсказке/разборе, M5 принимает фактическую итоговую страницу.

## Вход и сбор контекста

1. Прочитай [общие правила](../../../docs/make%20les%20stage/AGENTS.md) и [маршрут M1–M5](../../../docs/make%20les%20stage/3%20stage/STAGE_FLOW.md). По последнему поручению установи ровно одно занятие: курс, главу/блок, строковый номер, паспорт, принятый MD, A/B, проектный старт, целевой TSX/source_file, точный ключ и формат практики, разрешённые привязки. История форка не меняет цель. Без принятого плана обозначь зависимость от отдельного Stage 2, не создавай план внутри Stage 3.
2. Для существующих источников выполни из корня `python tooling/courses/lesson_tools.py context --chapter chapter_01 --lesson 12.1`. При неоднозначности выбери `--source` вместо `--lesson`; открой найденные источники. UNKNOWN не разрешай выдуманным ID или поздним HEAD проекта. Для нового результата используй принятый план и назначенные пути; отсутствие будущего TSX или mapping не блокирует написание.
3. Определи первый неполный M-шаг по файлам. В CREATE начни с B и нужного самостоятельного действия. В REWORK сначала найди конкретный дефект объяснения/задачи и ожидаемое улучшение; принятые части сохраняй. Не составляй отдельное досье перед изменением, не повторяй полный аудит на каждом шаге.

## M1: создать теорию

Прочитай [M1](../../../docs/make%20les%20stage/3%20stage/01_THEORY_DRAFT.md) как план и правила, исполни [stage-3-theory-author](../stage-3-theory-author/SKILL.md). В целевом TSX подготовь понятный вход, причинные объяснения, независимые полные примеры и опоры для всех обязательных операций будущей практики. Проверь изменённый исполняемый пример с заявленного старта; не добавляй неизученные инструменты в ученический код. При первой схеме/интерактиве сразу используй visual-author и осмотри результат с соседним текстом.

## M2: создать практику

Прочитай [M2](../../../docs/make%20les%20stage/3%20stage/02_PRACTICE_DRAFT.md), исполни [stage-3-practice-author](../stage-3-practice-author/SKILL.md) для точной записи практики. Каждая задача даёт понятные старт, действие и критерий до раскрытия ответа; условие объясняет спокойно и подробно, ТЗ перечисляет критерии готового результата техническим языком по порядку. Сверь операции с уже написанной теорией: нужную опору добавь в M1 в разрешённом объёме либо укажи точный неразрешённый пробел. В полном Stage 3 это обычное адресное исправление, не новый этап. Скрытые тесты и эталоны не попадают в публичную выдачу.

## M3: отредактировать учебный маршрут

Проверь последовательный разбор по [M2](../../../docs/make%20les%20stage/3%20stage/02_PRACTICE_DRAFT.md#понятный-разбор-решения), передачу файлов и ограничений соседним карточкам и состояние интерактива до ответа. Исправляй найденное через профильный skill; технические проверки не подменяют эти три результата.

По [M3](../../../docs/make%20les%20stage/3%20stage/03_CONTENT_EDIT.md) прочитай теорию в видимом порядке, затем задания без помощи и разборы. Найди сложную формулировку, скачок знаний, оторванный пример, повтор или лишнюю проверку. Для дефекта текста/примера примени нужную операцию theory-author, для условия/ТЗ/разбора — practice-author; исправляй адресно, без повторного полного написания M1/M2. Сохрани единственное объяснение, необходимую аналогию и полезный визуал. Технический PASS не доказывает понятность.

## M4: довести визуал и композицию

Прочитай [M4](../../../docs/make%20les%20stage/3%20stage/04_VISUAL_INTERACTIVE.md), исполни [stage-3-visual-author](../stage-3-visual-author/SKILL.md) для элементов и всей композиции. Проверь учебную функцию, логику чтения, нагрузку, реальные состояния, адаптивность и полную ширину внешних блоков относительно контента. Исправь и повторно осмотри затронутое. Ранний просмотр при создании сохраняется; M4 принимает композицию целиком.

Для раннего просмотра открой context.preview_url через встроенный браузер только на http://127.0.0.1:5173/. Если TSX ещё без mapping, сначала сохрани его, открой http://127.0.0.1:5173/authoring.html и введи назначенный путь относительно apps/web/src/lessons/ без расширения. Не меняй общий каталог ради просмотра. Проверь контейнеры 1120/720/360 px, значимые состояния и сброс; образцы доступны по `?lesson=examples`. Этот просмотр не принимает backend-практику или всю платформу на мобильном viewport. Локальный вход и доступы для итоговой платформы — в STAGE_FLOW.

## M5: принять сохранённое занятие

Прочитай полный [M5](../../../docs/make%20les%20stage/3%20stage/05_LESSON_ACCEPTANCE.md) и выполни его предметные критерии и четыре технических уровня на итоговой версии: backend, frontend, фактическая выдача без утечек, открытая страница/runner. Проверь каждую обязательную задачу, подходящие верный/неверный/пограничный случаи и всю теорию/практику на нужных ширинах и состояниях. После исправления повтори затронутое; используй прежнее evidence только при той же версии и зависимостях.

`python tooling/courses/lesson_tools.py check --chapter chapter_01 --lesson 12.1 --stage 3` проверяет свою реализацию статически; при неоднозначности укажи `--source`. FAIL исправь в своём scope, UNKNOWN установи адресно. STATIC_ONLY, сборка и ранний preview не заменяют API, runner, браузер и полный M5. При недоступности обязательного уровня выполни независимую работу и назови конкретный NOT_VERIFIED/блокер; COMPLETE не присваивай.

Выход: созданные и интегрированные TSX/практика с полной M5-приёмкой либо конкретный остаток. Сохраняй ID, строковые номера, экспорты, source_file, точные ключи, порядок задач, приватные проверки и чужие правки. Обычный scope автора не включает shared/CSS, загрузчики, другие уроки, концепты или StudyHub. Форк не изолирует общие файлы: перечитай актуальный участок перед записью, не очищай общий diff. Итог — результат, фактические проверки и остаток; отдельные отчёты по M-шагам не нужны. После своего Stage остановись; другое занятие, Stage или чат автоматически не запускай. Явно ограниченный шаг/фрагмент выполняй только в его границах.

Канонические критерии: [каркас и простой рассказ M1](../../../docs/make%20les%20stage/3%20stage/01_THEORY_DRAFT.md#обязательный-каркас-обычного-занятия), [самостоятельность M3](../../../docs/make%20les%20stage/3%20stage/03_CONTENT_EDIT.md#приёмка-самостоятельности-по-теории). Прямое поручение на фрагмент сохраняет свои границы; не запускай остальные Stage или отдельный отчёт ради этой проверки.
