# Законченные объяснения для автора

Это образцы формы, не обязательный текст урока и не новые задания. Проверены локальным Python; перед переносом проверь предпосылки, независимость от практики и вывод своей версии. Полные требования M1 сохраняются.

## Условие: сначала смысл, затем граница

Предпосылки: переменная, целое число, сравнение, print. Новое: if и отступ тела. Практика может применять условие к другому предмету; не повторяй её функцию и данные.

Программе нужно показывать сообщение только при температуре ниже нуля. `temperature < 0` даёт истину или ложь. `if` выполняет строки с отступом, когда условие истинно; иначе пропускает их. Следующая строка без отступа выполняется в обоих случаях.

Файл temperature.py:

```python
temperature = -1
if temperature < 0:
    print("Ниже нуля")
print("Проверка завершена")
```

Запуск: `python temperature.py`. Вывод:

```text
Ниже нуля
Проверка завершена
```

При -1 условие истинно, поэтому печатаются обе строки. Теперь поменяй только -1 на 0 и запусти снова. Результат: единственная строка `Проверка завершена`. Ноль не меньше нуля, поэтому тело if пропущено. Для включения границы понадобилось бы `<=`. Схема двух исходов помогает увидеть именно это различие. Перенос в практику: ученик сам выбирает условие по её правилу, а не копирует готовую ветку.

## Накопление: один шаг меняет известное состояние

Предпосылки: список, переменная, for, сложение, print. Новое: накопление промежуточного результата. Если требуется функция/return, объясни их отдельно до использования.

Считаем общую длину трёх отрезков. До цикла ещё ничего не просмотрено, поэтому сумма равна нулю. На каждом шаге прибавляем текущую длину к уже накопленной сумме.

Файл lengths.py:

```python
lengths = [3, 5, 2]
total = 0
for length in lengths:
    total = total + length
print(total)
```

Запуск: `python lengths.py`. Вывод: `10`. Состояния total: 0 → 3 → 8 → 10. Если заменить список на `[]`, цикл не сделает ни шага, останется 0. print находится после цикла: он показывает один итог, а не промежуточные суммы. Контраст для автора: print с отступом внутри цикла вывел бы 3, 8, 10 на отдельных строках; показывай этот вариант только с полным кодом и явной целью.

Перенос: практика считает другую величину тем же изученным механизмом. Она не требует sum, генераторов, assert или новых способов проверки. По условию ученик знает вход, требуемое действие и наблюдаемый итог.

## Вместо перечня API: прочитать одно наблюдение

Авторский пример для темы SQLite после объяснения соединения, CREATE TABLE и PRAGMA. Плохая подача: «table_info возвращает cid/name/type/notnull/dflt_value/pk; далее сравниваем всё с моделью». Она называет поля, но не учит сделать вывод.

Понятный ход: «Модель говорит: название книги обязательно. Проверим, записано ли правило в файле. Из table_info выпишем строку title: `(0, 'title', 'TEXT', 1, None, 0)`. Значения идут по порядку: номер столбца, имя, тип, флаг NOT NULL, SQL default, признак ключа. В этой строке смотрим на четвёртое значение: 1 означает явно заданный NOT NULL. Если в определении обычного title такого ограничения нет, увидим 0 и запишем конкретное расхождение. Пока ничего не исправляем: выясняем, что ожидали и что нашли».

Покажи эту одну строку как подписанное сравнение «ожидали → наблюдали → вывод». Затем предложи такой же небольшой перенос на другом обычном текстовом поле с разобранным результатом. Только после этого переходи к самостоятельной описи модели проекта. Особые случаи PRIMARY KEY и полный набор объектов схемы не надо смешивать с первым объяснением notnull; если они требуются заданием, им нужна своя подготовка.

Перед первым большим скриптом отдельно раскрой вопрос и новую операцию. Безопасную подготовку и закрытие соединений сохрани, но не прячь за ними предметную разницу. Объяснение готового результата не заменяет возможность ученика самому выбрать следующий шаг.
