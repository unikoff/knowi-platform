# Технические работы

Заглушку обслуживает отдельный Nginx. Она закрывает внешний трафик, но не
останавливает внутренние процессы и записи в базу. Текущая подготовка не включает
её в production; перед применением подтвердите контекст и namespace, внешние
входы, Traefik entrypoints и приоритеты, TLS Secrets, доступность проверенного
frontend image и отсутствие конфликтующих ресурсов `knowi-maintenance`.

## Включить и выключить

Из корня репозитория задайте явный Kubernetes context:

```powershell
python infra/gitops/operations/maintenance.py --context $ctx on
python infra/gitops/operations/maintenance.py --context $ctx off
```

Перед `off` убедитесь во внутренней готовности приложения. При включении команда
проверяет готовность Nginx и брендированный ответ 503 на настроенных публичных
входах. При выключении сначала удаляются маршруты и проверяется возвращение
главной страницы и JSON-каталога Core; при неудаче маршруты восстанавливаются. Backend
удаляется только после успешных проверок.

При необходимости `--release-file <путь>` передаётся до `on`, `off` или `run`
для выбора release с закреплённым frontend digest. `--timeout` задаёт предел
ожидания сходимости Kubernetes и HTTP, но не продолжительность команды работ.

Правила перехватывают пути исторических входов `knowi.ru`, `www.knowi.ru`,
`13-140-29-11.sslip.io` и `13.140.29.11` по HTTP и HTTPS. HTTP сохраняет доступ
к `/.well-known/acme-challenge/`. HTTPS использует `knowi-tls` для доменов и
`preview-tls` для sslip.io и IP. Проверьте актуальность этих настроек перед
применением. API возвращает 503 JSON, браузерные пути — HTML с `no-store`.

## Операция с защищённым окном

Подготовьте JSON-файл с двумя обязательными массивами аргументов `operation` и
`check`. Пример ниже ссылается на **файлы оператора**, которые нужно заранее
создать и проверить; в репозитории готовых скриптов для этой операции нет:

```json
{
  "operation": ["python", "operator-cutover.py"],
  "check": ["python", "operator-check.py"]
}
```

```powershell
python infra/gitops/operations/maintenance.py --context $ctx run $workflow
```

`operation` должна выполняться в foreground на протяжении всего окна: остановить
writers, выполнить backup и DDL, запустить нужные компоненты и дождаться всех
удалённых Job. `check` должна подтвердить внутреннюю готовность, корректность
данных и endpoints до открытия трафика. Оба массива запускаются напрямую, без
неявной оболочки; если нужны последовательности команд, оформите их в проверенных
скриптах оператора. Команда передаёт в них `KNOWI_MAINTENANCE_CONTEXT` и
`KNOWI_MAINTENANCE_NAMESPACE`. Используйте эти значения для вызовов `kubectl`.
`run` отклоняет уже включённую заглушку.

Защитная блокировка с идентификатором операции хранится в Kubernetes. При ошибке
`operation` или `check`, а также исчезновении процесса блокировка сохраняется и
маршруты остаются закрытыми. Сначала выясните результат и убедитесь, что прежний
процесс и удалённые Job остановлены, а приложение внутренне исправно. Затем
используйте идентификатор владельца операции:

```powershell
python infra/gitops/operations/maintenance.py --context $ctx off --recover $operationId
```

Восстановление проверяет совпадение идентификатора. Не повторяйте миграцию с
неизвестным результатом, пока не проверены состояние Job и фактическая схема.

Автоматическое окно действует только для операций, запущенных через `run`.
Прямой ручной DDL или запуск Job его обходят; возникшая авария сама заглушку не
включает. Обычные CI и Argo sync не изменены: имеющийся canary analysis зависит
от доступности публичного сайта, а универсального исполнителя миграций нет.

Для офлайн-подготовки манифестов по-прежнему доступен
`prepare_maintenance.py`; он не обращается к кластеру. Nginx сохраняет 503 при
подстановке страницы: [документация `error_page`](https://nginx.org/en/docs/http/ngx_http_core_module.html#error_page).
