## Shared client signature update — actor and target lifecycle (supersedes Phase 3 signature)

```ts
fetchActivityReport(filters: ActivityReportFilters, expectedActorRef: string, signal?: AbortSignal): Promise<ActivityReportV1>
// filters = { from_time, to_time, course_id?, subject_ref?, user_id?, expected_target_ref? }
// subject_ref and user_id are mutually exclusive. expected_target_ref is local-only and requires user_id.
```

Pass authenticated `user.account_ref` as the required second argument; missing/invalid reference fails closed. On grant response the client compares `subject_ref` to that actor before any Query request. UI callers must cancel/remount by auth revision and account lifecycle as well as course/target/period. For a numeric target pass `user_id`; when roster provides the selected person's `account_ref`, also pass it as `expected_target_ref` to reject a recycled numeric ID. Core resolves the target and returns `target_subject_ref`, which the client checks as a UUID (and compares to `expected_target_ref` if given) and sends as Query `subject_ref`. `user_id` and the optional expected target are never sent to Query; expected_target_ref is not sent to Core either. Direct `subject_ref` continues to be passed to both grant and Query. Server authorization remains mandatory; no token or IDs are logged/stored by the client.

The actor/target update is implemented and source-checked: `PlatformAdmin` includes account lifecycle in its mount key; `PlatformAnalytics` passes actorRef into the client and includes it in its request key. Missing actor fails closed before network.
