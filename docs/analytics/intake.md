# CORP-77: транспорт Collector

Только `POST /api/analytics/events/batch` в процессе collector. Авторизация: общий validated trust manifest, локальная Ed25519-проверка grant user/collect и серверная идентичность `browser:<subject_ref>`; source и subject из browser body не принимаются. Локальная проверка subject fence обязательна; реализованный `PostgresIntake` повторяет её под общей subject lock в транзакции факта и jobs. Нет public control endpoint, Core issuer, Tracker и report handler. При отсутствии manifest, runtime зависимостей или закрытой readiness endpoint возвращает503; `/ready` остаётся503 до полного privacy restore barrier. HTTP сам по себе не включает реальный сбор.

`ANALYTICS_TRUST_MANIFEST_JSON` — общий для ролей JSON с `grant: {issuer, keys}` и `producer: {issuer, keys, allowlist}`. Ключи публичные Ed25519, rings обязаны иметь разный материал. Независимая role-specific конфигурация вместе с manifest запрещена; query получает grant verifier из того же manifest. Процесс вычисляет `app.state.trust_manifest_fingerprint` по нормализованному JSON. Сверка единого источника и fingerprint **между разными процессами/узлами** относится deployment/runtime gate; один процесс не может доказать отсутствие drift на другом. Без принятой общей конфигурации нельзя включать оба trust domain или будущий Query. Приватные ключи не передаются приложению.

Ограничения: 256 KiB фактических байт запроса, 100 items, 4096 байт каждого JSON item, 1–100 concurrent requests на процесс из Settings и общий deadline `db_timeout_seconds` (до 30 с). ASGI middleware ограничивает bytes по мере чтения без полного буферизования превышающего запроса. Это локальное ограничение, не распределённая квота; балансировка/лимиты всех реплик — CORP-80. Неверный JSON/envelope → 400, большой batch → 413; неверный grant → 401 с `WWW-Authenticate`, отказ scope/fence → 403, перегрузка → 429 с `Retry-After`, недоступность/unknown outcome → 503. Корреляция случайным UUID, входной body, credentials и диагностические исключения не возвращаются и не логируются.

Корректный envelope обрабатывается независимо по items: malformed/oversized/unsupported → rejected, неизвестная product course/catalog/lesson версия → pending без факта. Перед первой записью все валидные events проверяются на course scope; один неразрешённый course отклоняет запрос целиком. `accepted`, `duplicate`, `conflict` приходят только от `IntakePort`. Timeout, потеря ответа,429/503 означают неизвестный исход: повторить те же batch/event IDs и payload с bounded backoff/jitter. Если grant истёк после accepted/duplicate предыдущего item, ответ503 явно требует refresh credential и retry тех же ID; если между items выиграл tombstone —503 после предыдущего durable receipt, но обычный403 до первой возможной записи. Первичный невалидный grant даёт401, начальный запретscope/fence —403. Нет ACK не означает нет записи; новые ID для повтора не генерируются.

Публичный порт `IntakePort.accept(record, *, deadline)` принимает server-built `AcceptedEvent` и абсолютный monotonic deadline. `PostgresIntake` является default adapter и атомарно сохраняет факт и два synthetic jobs; accepted/duplicate возвращаются после commit. Metadata `build_record` назначает server received_at без изменения клиентских timestamps. Clock policy применяется в транзакции только к новому ключу: future_clock/too_late → явный per-item rejected без факта/jobs. Уже committed duplicate/conflict не переоценивается по текущему времени, включая повтор через8дней. `CatalogPort` пока не имеет default trusted projection; early fence и restore readiness тоже закрыты. Поэтому стандартный runtime остаётся503 даже с существующим DB adapter.

OpenAPI экспортируется из фактического collector router, плюс отдельно помеченный `planned` query. HTTP tests покрывают signed grants, limits, ACL, partial/unknown outcomes. Реальный PostgreSQL suite дополнительно проверил HTTP→fact+jobs, lost reply/retry, clock rejection и истечение grant/tombstone между items. Его readiness/catalog/early fence — явно synthetic doubles; commit fence настоящий DB check. Это не полный privacy protocol, не Core issuer и не deployment PASS. Distributed rate limits —CORP80, worker—81, deletion/recovery—427/65.
