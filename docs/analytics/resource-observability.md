# Analytics: локальный снимок ресурсов PostgreSQL

Статус: **read-only инструмент и одно локальное синтетическое наблюдение**, не нагрузочное испытание и не оценка production. Не останавливать процессы и не менять настройки Docker/WSL ради снимка.

```powershell
python -B services/analytics/tools/resource_snapshot.py
python -B -m unittest discover -s services/analytics/tests/observability -p test_resource_snapshot.py -v
```

Перед чтением инструмент требует локальный Docker endpoint из явного allowlist; переменные переопределения Docker endpoint/config приводят к отказу. Он сверяет точные имя, работающий контейнер, Compose project/service, synthetic label, фактический loopback binding, отдельный named volume и его Compose ownership, CPU и memory caps. После проверки использует неизменяемый container ID. При несовпадении identity или ошибке команды выдаётся только ограниченный код отказа. Неопознанный endpoint, Core и другие контейнеры не принимаются.

Допустимые операции: один `docker stats --no-stream`, фиксированные `docker exec --user postgres` команды `df -Pk` для data filesystem и `du -sk` для `pg_wal`. SQL, список процессов, текст запросов и журналы не читаются. Результат содержит только UTC timestamp, фиксированные статусы и численные значения. Исходные Docker metadata, credentials, labels, имена пользователей, container ID и пути не выводятся.

`cpu_percent` — однократное наблюдение Docker, а не прогноз нагрузки. `memory_used_bytes_approx` и `stats_memory_limit_bytes_approx` рассчитаны из округлённого отображения Docker stats; `memory_limit_bytes` и `cpu_limit_cores` — настроенные limits. WAL значение показывает занятие диска в единицах 1 KiB по `du`, не скорость генерации или полноту архива. `df` описывает видимую контейнеру файловую систему Docker/WSL: её свободный размер **не является** свободным пространством Windows-хоста, не гарантирует доступного места под данные и не измеряет оставшуюся квоту volume. Если `pg_wal` перенесён в symlink/отдельный mount, метод необходимо отдельно пересмотреть до интерпретации значения. Локальный socket не доказывает состояние production или работоспособность бэкапа.

Фактический снимок 16.11.2026 18:28:40 UTC: endpoint, identity контейнера и volume проверены; CPU 4.06% при cap 0.5 ядра, memory около 63,344,476 из 402,653,184 bytes, WAL 33,562,624 bytes, `df` доступно 1,020,839,727,104 bytes в видимой виртуальной файловой системе. Все значения моментальные; остаток виртуальной FS не снимает ограничение по доступной RAM/месту хоста. Соединения и ожидания блокировок PostgreSQL в этом снимке **не измерялись**.

Стенд K3s и дополнительные приложения остаются за отдельной проверкой ресурсов и разрешёнными ограничениями; снимок сам по себе не разрешает их запуск, изменяет инфраструктуру или отправляет уведомления.
