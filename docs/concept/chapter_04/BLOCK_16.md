**1. Основная тема и назначение.** Выделить один ожидаемый сбой доступности SQLite. Учебное действие — точная классификация по причине.

**3. Точка B.** Сам реализует распознавание SQLITE_CANTOPEN по SQLite-коду и доказывает, что ожидаемый тип получает безопасный отказ, ошибочная схема остаётся внутренней ошибкой.

**4. Необходимые темы в порядке изучения.**

- **00 / LinkedNotes** — **Точка старта.** Planner уже работает с одной SQLite. На учебной копии можно безопасно проверить, что случится, когда файл открыть нельзя. **Новый вопрос.** Как по причине отличить недоступную базу от ошибки в нашем запросе или схеме? **Результат.** Недоступная база даёт понятный штатный отказ. При другой внутренней причине клиент видит обычную ошибку сервера.
- **Объяснение.** Показать DBAPIError.orig, получение sqlite_errorcode и основной код SQLite для расширенных кодов (младший байт). Неизвестный или отсутствующий код распространяется дальше. SQLAlchemy может обернуть CANTOPEN и отсутствующую таблицу в один тип исключения. Проследить границу ресурса API/CLI, закрытие и перевод только известной причины через StorageError. Сохранить 404/422, не превращать другие сбои в ложный успех/409/совет исправить ввод. Лог по фиксированному имени причины, публичное сообщение без SQL, параметров, пути или traceback.
