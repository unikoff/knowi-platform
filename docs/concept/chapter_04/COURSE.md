**B16 = B главы.** Обычные API и CLI используют один локальный `DATABASE_URL`, общий сервис и полный SQL-репозиторий. Engine и фабрика переиспользуются внутри сборки; одна короткая Session покрывает HTTP-запрос к Planner или распознанную CLI-команду с данными. Успех записи следует после commit прикладного изменения. Сохранены данные, исходная схема TaskRow и внешний договор ниже. Для `SQLITE_CANTOPEN` есть безопасный HTTP 503 и понятный отказ CLI. Неожиданная ошибка идёт по внутреннему пути с безопасным публичным HTTP 500. Проверены rollback до commit, сохранённое изменение после commit и следующий успешный запрос. SQL-диагностика по умолчанию выключена; одно свойство запроса защищено регрессией. Есть проверенные README, зависимости, тесты и безопасный образец настроек для чистого запуска. Код, тесты и инструкция передаются без рабочих баз, архивов, журналов с данными и секретов. Явный init создаёт исходную схему и сохраняет строки при повторе. Старый JSON читается только отдельным импортёром по явному вызову с новым пустым SQL-назначением; обычный запуск и init сами снимок не импортируют. Ориентир формы проекта — StudyHub S `636d23c522d16330f513b99aa38a1355880a382c`. Доказательство учебного результата дают действия 76–80.

**Сохранённый договор Planner.** Публичная Task содержит id, title, priority, is_done. Id положительный, priority 1–5, HTTP title после обрезки имеет 1–120 символов. При переносе допустимые прежние CLI-заголовки и дубли title сохраняются, запись без tags получает пустой список. Сверяются id/title/priority/is_done/tags и Python `title.lower()` в `title_normalized`. POST возвращает 201 и id базы, PUT сохраняет внутренние данные, PATCH пропускает отсутствующее и null, применяет False, пустой патч не пишет. Повторный done сохраняет состояние без повторной записи. DELETE возвращает пустой 204. Отсутствующий положительный id даёт 404, невалидный ввод — 422. Фильтрация предшествует сортировке по id и limit; HTTP default 10 и диапазон 1–50, полный список CLI без HTTP-лимита. Статистика `all/open/done` отображается в HTTP как `total/open/done`. Поиск использует `query.strip().lower()` и буквальную подстроку, включая кириллицу, кавычки, % и _. Cookie preferences хранит вид интерфейса.
