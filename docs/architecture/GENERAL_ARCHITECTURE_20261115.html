Общая картина

knowi состоит из общей веб-оболочки, общего Core API и подключаемых пакетов курсов. Core сейчас — модульный монолит: основная серверная логика работает в одном приложении. Обработчик уведомлений запускается отдельным процессом из того же пакета. PostgreSQL хранит постоянные данные, Redis обслуживает сессии. Материалы курсов хранятся в репозитории, отдельно от пользовательского прогресса в базе.

Браузер → Web: общая оболочка + страницы выбранного курса
Браузер → /api → Core API
                 ├─ PostgreSQL: аккаунты, прогресс, заявки
                 ├─ Redis: сессии
                 ├─ адаптер курса → серверный пакет курса
                 └─ адаптер исполнения → Python-процесс

PostgreSQL: очередь уведомлений → Core worker → Telegram
Core API → почтовый транспорт SMTP → почтовый провайдер

Это логическая схема действующего кода. Web отображает интерфейс, Core принимает решения о доступе и сохранении данных, пакет курса поставляет учебное содержание. Лабораторный Runner pool и будущая Analytics в эту основную цепочку на схеме не включены.

Как устроены курсы

В реестре включены два продукта: backend и backend_copy. Первый — исходный курс Python Backend; второй — независимый пакет, созданный как его копия. Оба используют общие Web и Core, но имеют собственные ID, URL, настройки и материалы.

courses/
  registry.json
  backend/                       # пакет одного курса
    course.yaml                  # ID, URL, программа, пути подключения
    personal.settings.yaml       # серверные настройки продукта
    backend/
      catalog.py                 # каталог и правила курса
      plans/                     # планы и теоретические материалы
      practice/                  # задания и приватные проверки
    frontend/
      course/                    # страницы занятий, метаданные, изображения
      landing-personal/          # лендинг личных занятий
      landing-course/            # лендинг курса
    archive/                     # исторические материалы
  backend_copy/                  # та же структура, собственные исходники
  shared/
    ui/                          # общие учебные компоненты и стили
    demo/                        # примеры, галерея /backend/demo
    backend/                     # общий SDK каталога
    ai/                          # skills и роли для авторов

course.yaml описывает продукт и точки подключения. Реестр сообщает платформе, какие пакеты включены. Web получает из manifests браузерные entrypoints, Core — серверный каталог. Новый курс подключается пакетом и записью в реестре, без ручного добавления его ID в общий код платформы.

Аккаунт и подписка общие. Прогресс, решения и сохранённое состояние интерфейса разделяются по course_id. Собственная папка курса означает самостоятельность его содержания, а не отдельный сервер, базу или копию аккаунтов.

Серверные материалы, приватные проверки, personal.settings.yaml, архив и AI-инструкции не являются точками входа публичной браузерной сборки. courses/shared/ai/ — инструменты создания материалов; это не отдельный работающий сервис AI Mentor.

Как проходят основные действия

  1. Открытие курса. Общая оболочка выбирает зарегистрированный продукт, подключает его страницы и получает разрешённый каталог и прогресс через Core. Авторские материалы берутся из пакета курса; пользовательские результаты — из базы.

  2. Работа с практикой. Web отправляет решение в Core. Core определяет курс и задание, применяет правила проверки и доступа, обращается к исполнителю при необходимости и сохраняет результат. Отдельный запуск в интерпретаторе возвращает результат исполнения.

  3. Заявка или бронирование. Форма относится к конкретному продукту, а обработка и сохранение выполняются общим Core. Предназначенное для Telegram уведомление попадает в outbox; worker обрабатывает его отдельно.

Размещение и выпуск

Инфраструктурный контур проекта — VPS с K3s. Traefik принимает входящие запросы и направляет их к нужному приложению; Web отдаётся контейнером с Nginx, API обслуживает Core. Конфигурации находятся в infra/helm/ и infra/gitops/. Локальные стенды предназначены для разработки и проверок.

Исходники → GitHub Actions → образы в GHCR
          → версии в GitOps → Argo CD → приложения в K3s

Выпуск связан с веткой Release. Перенос файлов или успешная локальная сборка сами по себе не обновляют сервер. По последней записи проверки от 15 ноября 2026, рабочий AlphaVPS ещё использовал прежнюю GitOps-ревизию; выкладка текущего кандидата отдельно не подтверждена. В рамках подготовки этой страницы live-кластер не проверялся.

Поэтому эта страница фиксирует современную организацию кода. Точную версию работающих контейнеров, текущую маршрутизацию и готовность очередного выпуска проверяют отдельно. Подробности процедуры — в документации выпуска и эксплуатационных инструкциях.
