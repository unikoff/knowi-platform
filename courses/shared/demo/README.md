# Каталог доступных компонентов

Открыть при запущенном web app: http://127.0.0.1:5173/backend/demo

Это витрина возможностей общей библиотеки, а не сборка фрагментов занятий.
Каталог не импортирует `chapter_*`, не обходит TSX занятий, не использует
`source-inventory.json` и не зависит от появления новых материалов курса.
Стандартная обложка использует общий `LessonMetadataProvider`: его `source` —
ключ метаданных для показа действующего оформления, а не импорт TSX занятия.

## Состав и владение

- `examples.tsx` — явный реестр инструментов и специально подготовленные демонстрации.
- `catalog.tsx` — типы и проверка уникальности реестра.
- `main.tsx` — меню и анимированная карусель.
- `demo.css` — компактная оболочка; стили самих компонентов приходят из `courses/shared/ui/index.ts`.
- `assets/` — локальные демонстрационные изображения для просмотра с увеличением.

Одна запись соответствует одному публичному компоненту из `courses/shared/ui/index.ts`.
Разные применения и конфигурации находятся в его `variants`, а не становятся
новыми пунктами каталога. Все элементы конструктора схем показываются вместе
в одной карточке `Diagram`; `TypeCard` входит в `TypeCards`.
У `Section` один заголовок и несколько связных абзацев на нейтральную тему: обычный текст,
жирное и курсивное выделение, смысловой акцент, встроенный код, зачёркивание и ссылка.
Обёртки, служебная навигация и алиасы существующих инструментов не дублируются.
У `RichHero` только один пример: обложка занятия с номером и названием блока
и тематическими тегами. `LessonMetadataProvider` принимает resolver курса; без
него используется нейтральный fallback для авторского preview.
`TerminalDemo` использует `CodeBlock`, а `KeyTakeaways` — `Checklist`, поэтому
не становятся отдельными инструментами в меню.
Частные схемы и модели, жёстко связанные с конкретным занятием, сюда не попадают.

Чтобы добавить новую возможность, сначала нужен работающий переиспользуемый
компонент в общей библиотеке. Затем его добавляют в реестр с короткими
демонстрациями возможностей. Для нового применения существующего инструмента
достаточно добавить слайд в его `variants`. Новый класс или новый общий компонент
для этого не нужен. `defineCatalog()` запрещает повторные API и ID, пустые
демонстрации и интерактивы без нескольких примеров.

Пять разделов меню: оформление, списки и карточки, вопросы и задания,
код и выполнение, схемы и таблицы. Числа считают инструменты, а не примеры.
Никаких заглушек несуществующих возможностей в реестре нет.

## Поведение и проверки

В оболочке остаются короткое название инструмента и стрелки с точками.
Переключение меняет прозрачность, положение и высоту. Выходящий слайд исключён
из фокуса и взаимодействия. Стрелки клавиатуры действуют только в навигации;
состояние задания сбрасывается при смене примера. Автопрокрутки нет.
Учитывается системное предпочтение уменьшенной анимации.

`#demo-catalog-data` содержит только метаданные реестра: количество инструментов,
демонстраций и список API. Это не отчёт о покрытии CSS-классов занятий.

Из `apps/web`:

```powershell
node node_modules/typescript/bin/tsc --noEmit -p ../../courses/shared/demo/tsconfig.json
```

Каноническая HTML-точка входа — `courses/shared/demo/index.html`. Platform bootstrap
переписывает её module URL `/courses/shared/demo/main.tsx` для dev и production,
сохраняя `/backend/demo` и `/platform/backend/demo`. Компоненты, изображения и
примеры принадлежат этому каталогу; app config подключает их к маршруту.

Тема использует настоящий `@platform/shared/theme` и platform tokens/base CSS.
Отдельной палитры у shared UI нет. Цвета синтаксиса и статусов используют те же
семантические переменные, что и платформа. SVG в `assets/` — фиксированные учебные
скриншоты, их цвета являются содержимым изображения и не меняются вместе с темой.

`platform-review-state.md` и JPG сохраняют исторические материалы предыдущей
визуальной проверки. Они не доказывают проверку текущего переноса.

## Контракты общей библиотеки

`QuizCard` покрывает короткие ответы, сравнение решений с кодом, поиск ошибки,
«Правда / Ложь» и несколько допустимых ответов при одиночном выборе.
Параметры: `question`, `description`, `options`, `correctIndex`, `explanation`,
`orientation`, `answer`. Расширенный вариант ответа задаётся объектом
`{ title, code?, description? }`. Правильный индекс может быть числом или массивом.

`RecallCard` объединяет текстовый вопрос и прогноз результата кода. Автор задаёт
`question`, необязательные `code` и `hint`, а в `answer` может передать текст,
разметку или `CodeBlock`. Ответ раскрывается по нажатию; пользовательский ввод
не требуется. Существующие вызовы `PredictOutput` используют тот же интерфейс,
сохраняя свои данные и подписи раскрытия.

Схемы всегда занимают всю ширину и отдельную строку контента, включая вертикальные
и авторские схемы. Отдельного модификатора ширины больше нет. Ограничения размеров
внутренних узлов сохраняют смысл форм; длинные цепочки переходят в вертикальную
компоновку, когда места для читаемых узлов не хватает.

В разделе «Списки и карточки» нумерованный `ol.lesson-list` и связанный список
`ul.lesson-list` входят в одну карусель `ContentList`; рядом находятся `LinkedNotes`
и `TypeCards`.
`LinkedNotes` используется только в секции 00 и последней секции занятия;
внутренние применения переведены на `ContentList` с сохранением текста.
У компонентов нет переключателя вариантов. Нативные списки без классов
получают тот же нумерованный или связанный вид автоматически.

Связанный список внутри контента по умолчанию занимает всю доступную ширину.
Ограничение — явное решение автора визуала: например, `maxWidth="32rem"`
у `ContentList`. Дополнительные материалы передаются в `children`: компоновка
автоматически размещает их справа при достаточной ширине контейнера и под
списком при нехватке места. Обычные соседние блоки секции сохраняют свой порядок;
они не становятся соседним материалом списка без явного объединения.
В каталоге показан базовый полноширинный вид. Пример явного решения автора:

```tsx
<ContentList items={items} maxWidth="32rem">
  <p>Пояснение к последовательности.</p>
  <CodeBlock code={code} />
</ContentList>
```

`LinkedNotes` не принимает соседний контент и всегда занимает отдельную строку
на всю ширину контента занятия.

`Checklist` — интерактивный список с произвольным `title` и массивом `points`.
Пункты отмечаются кликом по строке или клавишей пробела; счётчик показывает
число отметок. Состояние относится к текущему экземпляру компонента.
Существующий `KeyTakeaways` использует тот же интерактив с заголовком
«Главное из урока» по умолчанию.

`CodeSequence` имеет один вид — «Собираем порядок». Параметры `plainText`
и `label` удалены: все шаги показываются обычным текстом, название интерактива
единое. Содержимое существующих заданий и правильные последовательности сохранены.

Варианты ответа показываются только обычным текстом: без `code`, моноширинного
шрифта, подсветки и отдельных подложек у токенов. Общий `plainOptionText`
убирает оформление из старой JSX-разметки и обратных кавычек в подписях;
сам пример программы и обратная связь сохраняют своё оформление.

Общий вид вариантов задаёт `answer-options.css`: `answer-option` для кнопки,
`answer-options` для группы. Отступы 12×16 px, скругление 12 px, единый шрифт подписей
(фрагменты кода отдельно оформляет `CodeBlock`) и состояния hover, focus-visible, выбора, верного и неверного ответа.
Локальные классы компонентов отвечают за раскладку, а не переопределяют этот вид.

`LessonScreenshots` — единая подача фотографий и скриншотов. `images` хранит
оригинал, alt, название, пояснение и ссылку на источник. Небольшое изображение
в рамке обтекается текстом; на узком экране располагается над ним. Несколько
изображений переключаются кнопками шагов. Поле `action` выбирает действие при
нажатии: `"zoom"` (по умолчанию) открывает просмотр с режимами «Вписать» и
«100%», `"link"` открывает `sourceUrl`, `"none"` оставляет изображение
статичным. Ссылка на источник доступна отдельно во всех режимах. Esc закрывает
просмотр и возвращает фокус на превью.

`InteractiveTable` — обычная таблица со всеми данными, видимыми сразу.
`columns` — названия столбцов; `rows` — стабильный `id`, первая ячейка `label`
и остальные значения `values`. При наведении подсвечивается вся строка.
Значок в заголовке использует акцентный цвет. Отметок и сортировки нет.
На узком контейнере таблица прокручивается внутри своего блока.

Схемы используют общую шкалу отступов из diagrams.css: 16 px у рамок и блоков,
8 px между текстовыми элементами, 4 px у подписей стрелок. Горизонтальная связь
занимает 80 px, вертикальная стрелка — 24 px. Отступы сохраняются на мобильных;
развилки рассчитывают центры веток с учётом промежутка между колонками.
Индивидуальные стили схем меняют только смысловую компоновку, а не эту шкалу.
