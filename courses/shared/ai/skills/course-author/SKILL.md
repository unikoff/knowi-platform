# Author one course artifact

Use for an explicitly assigned course artifact. First establish course ID, Stage, target artifact, stable lesson ID/string number, allowed paths, and current user edits. Keep the work within the assigned course package; do not change shared app/Core consumers or unrelated lessons.

Read the applicable complete canonical methodic before writing: [Stage 1](../../../../../docs/make%20les%20stage/1%20stage/STAGE_FLOW.md), [Stage 2](../../../../../docs/make%20les%20stage/2%20stage/STAGE_FLOW.md), or [Stage 3](../../../../../docs/make%20les%20stage/3%20stage/STAGE_FLOW.md), together with the linked step documents and scoped project guidance. These methodics define requirements and acceptance; this skill only routes execution. Do not silently weaken or replace them.

Keep Stage boundaries: Stage 1 designs chapter and block passports; Stage 2 plans exactly one lesson; Stage 3 builds exactly one lesson. Stop at the assigned Stage. Explain prerequisites before practice; keep theory and practice aligned. Preserve stable IDs, source paths, ordering, progress, private checks, and existing edits. Distinguish planned preparation from demonstrated learner knowledge.

Use the app's existing theme variables and shared UI; never introduce a course-specific palette. Keep backend-private tests/reference answers out of public frontend resources. Before editing, inspect the current target and nearby integration contract; after editing, run the narrow checks available for that Stage and report exactly what was not exercised. A build or static check is not browser/API/runner acceptance.
