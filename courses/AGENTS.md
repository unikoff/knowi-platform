# Авторство курсов

- Выберите курс по `registry.json` и его `course.yaml`; работайте только в назначенном пакете.
- Канонические пути: `backend/plans`, `backend/practice`, `frontend/course`, `frontend/landing-personal`, `frontend/landing-course` внутри пакета. Пути manifest имеют приоритет над историческими примерами.
- Старые примеры `apps/web/src/lessons` / `services/core-api/content` больше не являются местом авторства. Не создавайте их заново.
- Полные Stage-методики в `docs/make les stage` сохраняют требования и границы этапов. Перенос путей не разрешает пропускать методику или менять другой Stage.
- Общие компоненты и CSS — `shared/ui`, примеры — `shared/demo`, общий backend SDK — `shared/backend`, переносимые AI skills/роли — `shared/ai`.
- Импортируйте `@course-ui`; цвета наследуйте от темы приложения. Не копируйте палитру в курс.
- Новый продукт подключается своей папкой и реестром; не добавляйте ID или route/loader вручную в общую платформу.
- Сохраняйте ID, прогресс, пользовательские правки и приватные проверки. Базы, токены и реальные адресаты не входят в шаблон курса.
- Команды создания, обновления версии и проверки — в `shared/README.md`. Проверка исходников/SSR/сборки не является доказательством браузера, API или Runner.
